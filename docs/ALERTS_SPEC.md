# 경고 및 의존성 규격

## 목적

`data/tasks.json`의 `dependencies`를 기준으로 선행업무 누락과 일정·위험 신호를 계산합니다. 경고는 업무 완료를 막지 않으며, 사용자가 확인 후 진행할 수 있습니다.

## 의존성 규칙

- `dependencies`에는 존재하는 업무 ID만 기록합니다.
- 하나라도 미완료인 선행업무가 있으면 해당 업무는 `BLOCKED`로 표시합니다.
- 선행업무 완료·취소 시 화면을 다시 불러오지 않아도 카드 경고가 다시 계산됩니다.
- 차단 업무를 완료하려 하면 미완료 선행업무 ID와 업무명을 보여 주고 `취소` 또는 `그래도 완료`를 선택하게 합니다.
- 업무 원본과 경고 결과는 `localStorage`에 저장하지 않습니다.

## 경고 유형

| 유형 | 조건 |
| --- | --- |
| `BLOCKED` | 선행업무 중 미완료가 존재함 |
| `OVERDUE_REQUIRED` | 기한이 지난 필수 업무 |
| `HIGH_RISK` | 미완료 고위험 업무 |
| `DUE_SOON_CRITICAL` | 마감임박 또는 당일인 고위험 필수 업무 |
| `PHASE_WARNING` | 진행 또는 완료 상태의 후속 단계 업무가 있고 이전 단계 필수 업무가 미완료임 |

완료 업무는 일반적인 활성 경고에서 제외하지만, 이전 단계 미완료 상태에서 완료된 후속 업무는 단계 흐름 이상을 알리기 위해 `PHASE_WARNING`을 표시할 수 있습니다. 순환 의존성은 `js/validator.js`가 DFS로 검출하고 콘솔에 업무 경로를 출력합니다. 경고 우선순위는 `CRITICAL`, `HIGH`, `MEDIUM`, `LOW` 순입니다.

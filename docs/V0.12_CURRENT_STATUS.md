# v0.12 현재 상태 및 반영 항목

## 판단

v0.11 이후에는 기능을 계속 추가하기보다 실제 운영업무 117건을 중심으로 시스템을 통합하고 담당자에게 검증받는 단계로 전환한다. `업무목록.csv`가 업무 문장과 순서의 정본이고, `data/tasks.json`은 구조화 샘플 20건과 업무 마스터 편집 검증용으로 유지한다.

## 이번 반영

- `data/checklist-metadata.json`에 CSV key 117건을 1:1로 등록했다.
- `data/checklist-metadata.schema.json`과 검증 함수를 추가했다.
- CSV와 메타데이터를 운영 task로 변환하는 연결 모듈을 추가했다.
- 대시보드, 일정, 경고, 예산 업무 선택, AI 비교의 운영 입력을 117건으로 전환했다.
- 운영 task 상태는 `localStorage.checklist`에만 저장하고 `tasks`와 중복하지 않는다.
- phase와 timing은 CSV 구간에서 연결하고, 종료 후 업무는 내용에 따라 종료처리·정산·결과보고로 나눴다.
- 담당자 검토 전 메타데이터는 `PENDING_REVIEW`로 표시한다.

## 아직 확정하지 않은 것

실제 담당자 확인 없이 required, riskLevel, 담당역할, 완료기준, dependencies, 예산연계를 확정하지 않는다. 현재 값은 안전한 임시값 또는 빈 값이며, 담당자 검토 후 해당 항목만 `REVIEWED`로 갱신해야 한다. 특히 개인정보 처리 업무의 실제 절차와 `3회 체크`의 의미는 임의로 해석하지 않는다.

## 다음 실증 순서

1. 담당자와 117건의 업무명·구간·수행시점·필수/조건부 여부를 검토한다.
2. 위험도·완료기준·선행업무·예산연계를 확인하고 메타데이터를 갱신한다.
3. 담당자 A의 실제 상태를 JSON과 HTML로 인수인계한 뒤 담당자 B가 별도 설명 없이 5~10분 내 다음 업무를 찾는지 확인한다.
4. 검증된 자료로 AI 누락점검의 신규·보강·중복 결과를 측정한다.
5. 실증 결과에 따라 localStorage 유지 또는 서버 DB 전환을 결정한다.

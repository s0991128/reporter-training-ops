# 예산·집행·정산 규격

## 목적

v0.5 예산 기능은 교육 운영비의 계획, 집행 상태, 지급 여부, 정산 대기를 관리한다. 실제 금액은 사용자가 브라우저에서 입력하며 업무 원본 데이터에는 저장하지 않는다.

## 원본 데이터

`data/budget-categories.json`이 예산항목의 단일 기준이다. 항목 ID는 `LECTURER`, `ACCOMMODATION`, `TRANSPORT`, `MEAL`, `SUPPLIES`, `ETC`를 사용한다. 운영 화면의 업무-예산 연결은 117건 CSV key에 병합된 메타데이터를 사용하며, 계획금액이나 집행금액은 업무 원본에 포함하지 않는다.

이 항목들은 기능 검증을 위한 샘플 분류이며 특정 기관의 실제 예산과목을 의미하지 않는다.

## 저장 구조

localStorage 키는 `trainee-reporter-training-state-v4`이며 사용자 상태만 저장한다.

```json
{
  "version": 4,
  "budget": {
    "plans": { "LECTURER": 8000000 },
    "transactions": []
  }
}
```

기존 v3의 설정, 업무 완료상태, 완료일, 메모는 v4로 자동 마이그레이션한다. 업무 제목, 설명, 단계 등 원본정보는 저장하지 않는다.

## 집행 계산

- `PLANNED`: 계획 기록이며 가용액에서 차감하지 않는다.
- `COMMITTED`: 확정 집행액이며 가용액에서 차감한다.
- `PAID`: 지급액이며 가용액에서 차감하고 집행률에 포함한다.
- `CANCELLED`: 목록에는 남기되 집행 계산에서 제외한다.
- 가용액 = 계획예산 - 확정 집행액 - 지급액
- 집행률 = 지급액 / 계획예산 × 100
- 계획예산이 0이면 집행률은 0%로 표시한다.

예산 초과는 경고로 표시하며 입력을 차단하지 않는다. 지급 상태가 `PAID`이고 정산 상태가 `PENDING`이면 정산 대기 경고를 표시하고, 업무 완료 후 연결 지출이 없으면 업무·예산 연결 확인 경고를 표시한다.

## 실제 운영 입력 방법

교육 건별로 예산·정산 화면에서 항목별 계획예산을 먼저 입력한다. 지출이 예정되면 `PLANNED`, 집행이 확정되면 `COMMITTED`, 실제 지급 후에는 `PAID`로 수정한다. 지급 증빙을 별도 안전한 기관 절차에서 확인한 뒤 정산이 끝나면 `정산 완료`를 누른다. 취소된 건은 삭제하지 않고 `CANCELLED`로 남긴다. 업무와 연결할 때만 관련 업무를 선택하며 설명과 메모에는 개인정보를 쓰지 않는다.

## 개인정보

교육생 이름, 연락처, 주민등록번호, 계좌번호 등 개인정보를 입력 필드, JSON, localStorage에 추가하지 않는다. 지출 설명과 메모에도 개인정보를 기록하지 않는다.

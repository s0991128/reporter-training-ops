# 담당자 인수인계 모드 사양

## 목적

담당자가 바뀌어도 새 담당자가 프로그램을 열고 현재 진행상황, 미완료 업무, 진행중 업무, 메모, 최근 처리 내역을 바로 확인하도록 한다. `업무목록.csv` 117건은 계속 체크리스트의 Single Source of Truth이며, 인수인계 모드는 기존 업무 정의와 상태를 삭제하거나 대체하지 않는다.

## 현재 진행구간

구간 순서는 CSV의 행에 처음 나타난 순서를 사용한다.

1. 적용 가능한 업무(`NOT_APPLICABLE` 제외) 중 `COMPLETED`가 아닌 업무가 처음 존재하는 구간을 찾는다.
2. 뒤 구간에 완료·진행중·메모가 있는 업무가 있으면 실제로 진행된 가장 뒤 구간을 현재 진행구간으로 표시한다.
3. 현재 구간보다 앞선 구간의 미완료 업무는 별도 경고로 표시한다. 이 경고는 업무 진행을 차단하지 않는다.
4. 모든 적용 업무가 완료되면 `모든 구간 완료`로 표시한다.

진행률은 다음과 같다.

```text
완료 업무 수 / (전체 업무 수 - 해당없음 업무 수)
```

## 먼저 확인할 업무

다음 순서로 후보를 만들고 key 기준으로 중복 제거한다.

1. 이전 구간 미완료
2. `IN_PROGRESS`
3. 메모가 있는 미완료 업무
4. 현재 진행구간 미완료
5. 현재 구간의 다음 미착수 업무 또는 다음 구간의 첫 적용 업무

각 항목은 구간, 업무, 상태, 메모, 마지막 변경시각을 표시한다.

## 저장 데이터

localStorage 저장 버전은 v6이다. v5 이하의 데이터는 기존 업무·일정·예산·지출을 유지한 채 자동 보완한다.

```json
{
  "checklist": {
    "task-60": {
      "status": "IN_PROGRESS",
      "completedAt": null,
      "updatedAt": "2026-09-03T06:42:00.000Z",
      "memo": "증빙자료 회신 대기",
      "checks": []
    }
  },
  "checklistHistory": [
    {
      "taskKey": "task-60",
      "type": "STATUS_CHANGED",
      "from": "NOT_STARTED",
      "to": "IN_PROGRESS",
      "at": "2026-09-03T06:42:00.000Z"
    }
  ],
  "handover": {
    "note": "다음 담당자가 확인할 메모",
    "updatedAt": "2026-09-03T06:43:00.000Z"
  }
}
```

지원 이력 유형은 `STATUS_CHANGED`, `SUBCHECK_CHANGED`, `MEMO_UPDATED`이며 최근 200건만 유지한다. `MEMO_UPDATED`에는 메모 원문을 저장하지 않는다. 업무 메모와 종합 메모에는 주민등록번호, 전화번호, 계좌번호, 이메일 등 개인정보를 입력하지 않는다.

`updatedAt`은 완료 체크·완료 해제·해당없음 변경·3회 체크 변경·메모 저장 시 갱신한다. 기존 `completedAt`은 별도로 유지한다.

## HTML 보고서

`인수인계 보고서 만들기`는 서버와 통신하지 않고 현재 브라우저에서 self-contained HTML을 생성한다. 보고서는 다음을 포함한다.

- 생성일, 교육명, 현재 진행구간
- 전체·적용·완료·진행중·미완료·해당없음·진행률
- 먼저 확인할 업무, 진행중 업무 전체, 이전 구간 미완료 업무
- 메모가 있는 미완료 업무와 완료 업무의 메모
- 다음 업무, 최근 처리, 구간별 진행현황, 전체 체크리스트 상태
- 체크리스트 원본명, 행 수, key 수, checksum
- 종합 인수인계 메모

HTML은 읽기용 문서이므로 프로그램으로 다시 import하지 않는다. PC 이동과 데이터 복원에는 JSON 백업파일을 사용한다.

## 담당자 변경 절차

1. 기존 담당자가 운영데이터 JSON을 내보낸다.
2. 기존 담당자가 인수인계 HTML 보고서를 만든다.
3. 승인된 내부 수단으로 두 파일을 전달한다.
4. 새 담당자가 최신 프로그램을 실행한다.
5. 새 담당자가 운영데이터 JSON을 가져온다.
6. 인수인계 화면의 상태·메모·최근 처리 내역을 확인한다.
7. HTML 보고서와 프로그램 화면을 비교한다.

## 호환성

기존 백업 형식과 백업 버전은 유지한다. v0.10 백업에 새 필드가 없어도 정상으로 판정하고, 복원 시 `updatedAt: null`, 빈 `checklistHistory`, 빈 `handover`로 보완한다. 백업에는 기존 체크리스트 상태·3회 체크·메모·완료일과 새 인수인계 데이터가 함께 포함된다.

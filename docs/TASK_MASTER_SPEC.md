# 업무 마스터 운영 규격

## 목적

`data/tasks.json`은 업무 정의의 Single Source of Truth다. 현재 v0.7은 실제 110개 업무를 임의로 생성하지 않고, 검증용 20개 샘플만 제공한다. 브라우저의 업무 마스터 편집은 메모리 세션에서만 수행하며 원본 JSON이나 localStorage를 직접 변경하지 않는다.

## 관리자 원칙

- 일반 운영 화면에는 `active: false` 업무를 표시하지 않는다.
- ID는 `PRE`, `OPS`, `CLS`, `FIN`, `RPT` prefix와 단계가 일치해야 한다.
- 업무를 삭제하기 전에 다른 업무의 `dependencies` 참조 여부를 검사한다. 참조 중이면 삭제하지 않고 비활성화를 우선한다.
- 완료상태와 메모는 업무 원본과 분리된 localStorage v4 상태다. 향후 업무 목록을 교체할 때 ID가 유지된 상태만 보존하고 신규 ID는 미착수로 시작한다.

## CSV 계약

CSV는 UTF-8 BOM과 고정된 23개 열을 사용한다. `completionCriteria`, `dependencies`, `documents`, `tags` 같은 배열은 `|`로 구분한다. 문서의 필수 여부는 `문서명::required` 또는 `문서명::optional` 형식으로 표현한다. 반복 설정과 AI 점검 설정은 완전한 보존이 필요하므로 JSON 후보 파일을 사용한다.

CSV 가져오기는 파싱, 구조 검증, 품질 경고를 미리 보여준 뒤 정상 행만 편집 세션에 적용할 수 있다. JSON 내보내기는 구조 검증 오류가 없을 때만 활성화된다.

## 품질 점검

구조 오류와 품질 경고를 구분한다. 짧은 설명, 필수 업무의 완료기준 누락, HIGH 업무의 담당자·기준 누락, 예산항목 누락, AI 키워드 누락, 설명과 기준의 중복, 인수인계 공백은 경고로 표시한다. 품질 점수는 입력 완성도 참고값이며 담당자나 업무 성과 점수가 아니다.

## 실데이터 전환

실제 업무 목록은 CSV 템플릿으로 준비하고, 단계·ID·필수필드·의존성을 먼저 검증한다. 검증 오류를 모두 수정한 뒤 JSON 후보를 검토하고, 별도 백업 후 `data/tasks.json`에 반영한다. 반영 전후 업무 ID가 바뀌면 완료상태와 메모 연결에 영향을 주므로 ID 변경 목록을 별도로 확인한다.
